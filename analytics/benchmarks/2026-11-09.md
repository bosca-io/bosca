# Disk analytics queue measurements — 2026-11-09

Baseline before the append-only checkpoint cleanup. See the [cleanup comparison](2026-11-09-cleanup.md) for current implementation measurements.

The RAF queue sustained the tested 10,000 events/sec batched load on this host with bounded backlog, including after the two-minute deduplication window. This supports using it for that local queue workload. Deployment-volume performance and complete collector/processor capacity remain unmeasured; HTTP, transforms, Iceberg and object storage are excluded. No production rate/latency target was supplied.

Host: Apple M4 Max, 16 logical processors, 128 GiB RAM, local APFS SSD (approximately 94% occupied), macOS 27.0.1, GraalVM JDK 25.0.3. The benchmark JVM uses a fixed 1 GiB heap. The shared developer host was not isolated from other activity. All queue file/directory syncs, checksums, atomic checkpoints, two-minute scoped deduplication and default rollover remain enabled. Percentiles are 0.1 ms upper bucket boundaries.

Each short scenario ran three times after a 5,000-event enqueue/drain warmup. Tables report medians of trial results, not a pooled percentile. Ranges show trial throughput variation. Burst/enqueue timings are short finite workloads and must not be treated as sustained capacity.

20,000 events per trial. Both decoding and acknowledgment are included. Event-ID integrity passed in every run. Grouping is essential: atomic checkpoint replacement and directory sync cost milliseconds per acknowledgment. The production shared consumer requests groups of up to 100 deliveries.

These are short local drain measurements. In particular, the 100-event/100-delivery case has only two acknowledgment groups per trial. It demonstrates amortization, not a durable maximum-throughput SLO.

## Concurrent producer and consumer

The fixed-rate producer is paced against elapsed time and waits for each enqueue. The achieved rate is therefore reported separately from the target; a blocked producer does not create an independent upstream arrival backlog. Handoff latency includes creation, durable enqueue, segment rollover, polling and durable acknowledgment, sampled once per delivery. Total completion includes final drain.

## Abrupt producer restart

Each of three trials wrote 105,000 identified events, then halted an isolated writer JVM without closing/sealing its final 5,000-event open segment. Initialization, index loading and tail recovery took a median **50.1 ms**, range **34.9–68.4 ms**. Draining afterward verified all 105,000 IDs in each trial. JVM startup and cold-device-cache/power-loss recovery are excluded.

## Reproduction and remaining acceptance

See [benchmark instructions](README.md) and [raw run records](2026-11-09.json). Exact commands are stored with each raw run. Scratch spools were removed after measurement. No application data or deployment was changed.

Local queue measurements are complete for these cases. Overall SERVER-SPEC-12 acceptance still requires the recorded coverage gaps, native execution, full deployed broker-free topology, and deployment-specific workload/volume/retention testing with agreed latency and throughput targets. These benchmarks do not lower any coverage threshold or establish a production capacity guarantee.
