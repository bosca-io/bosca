# Independent disk analytics segments — 2026-11-12

Earlier retries now retain their own durable checkpoint while later segments continue and reclaim storage. One synced RAF journal carries segment updates; compaction writes independent segment snapshots before committing its journal revision and truncating. Retry-only segments release their reader slots, including zero-delay retries. Discovery alternates fresh work and retries, with bounded open readers and delivery claims. An idle discovery hint avoids repeated directory walks, refreshes on directory modification, and expires after 100 ms for coarse timestamps.

The measurements below use real file/directory syncs, checksums, scoped deduplication and rollover. Queue-only peak runs started after the endurance and native/test processes had finished. The local Iceberg endurance run overlapped other validation and is a sustained-load check, not an isolated peak-throughput measurement. All JVM benchmark processes used a fixed 1 GiB heap on the same APFS host as the [previous measurements](2026-11-09-cleanup.md). Raw trials, environment details and source/binary hashes are in [the JSON artifact](2026-11-12.json).

## Ten-minute local Iceberg endurance

The final run accepted **6,000,100 healthy events** over 600.00 seconds at an offered 10,000 events/sec, using 100-event batches. An earlier 10,000-event segment stayed pending and retried 119 times while later segments produced 601 real Iceberg commits. Every healthy event ID was read back exactly once. The failed segment remained recoverable after consumer restart; its final acknowledgment was synthetic scratch-data cleanup. Production has no automatic discard policy.

This workload uses minimal event envelopes with IDs. It exercises the production disk queue, protobuf staging, event-to-record transform, Parquet and local `HadoopTables` commits. It excludes HTTP, domain transforms, request scopes, the deployed catalog/object store and deployment-volume latency. Heap observations include uncollected garbage and do not establish a retained-memory bound. It is not a power-loss test.

## Native execution and tests

The maintained native queue smoke task built and ran separate producer/consumer processes under GraalVM 25 on macOS arm64. The complete native collector also built with `--no-configuration-cache`, became ready against an isolated pgvector/PostgreSQL 18 database with NATS and Redis disabled, and returned HTTP 202 after sealing a disk segment. Its scratch container and directory were removed. The collector-only fresh database logged the existing deferred analytics migration dependency on the scheduler schema; the HTTP/spool check does not claim analytics query installation completed.

The full analytics suite passed **832 tests**, and the collector passed **6 tests**, with no failures or skipped tests. Processor, server and runner Kotlin compilation passed. Regressions include delayed and immediate retries, more retrying segments than reader slots, a 4,100-segment deferred backlog, cross-process OS locks, partial append failure, quarantine directory-sync failure, stale cross-queue claims, compaction/restart, malformed checkpoints and real Iceberg progress past a failed transform.

Coverage is **99.52% line / 98.11% branch**. The unchanged gates are 99% / 98%; both measured gates pass. Production coverage exclusions and thresholds were not relaxed. The benchmark source set remains excluded from production coverage as before.
