# Disk analytics queue cleanup — 2026-11-09

The cleanup removes checkpoint file replacement from ordinary acknowledgments, avoids duplicate event identity/hash work, initializes the spool directory once, and caches status counters. Checkpoints append to a synced RAF journal, with a durable snapshot before periodic truncation. First-record revisions let independent observers detect journal resets even when it regrows beyond their cached offset. Frame-header and payload checksums distinguish corrupt lengths from incomplete appends.

The comparison uses the [original baseline](2026-11-09.md) and repeats its complete 39-case matrix on the same shared Apple M4 Max/APFS host with a fixed 1 GiB JVM heap. The final runs also include six cached-status cases and a 150-second endurance run. Syncs, checksums, scoped deduplication and count/age rollover remain enabled. The baseline and cleanup ran at different times without exclusive CPU/I/O control. Results reflect the combined cleanup rather than isolated contributions from each edit.

## Cached status

Each trial preloads a 5,000-event active segment with 4 KiB payloads, then checks 1,000 status calls per role while appending one event every ten calls. The producer uses its active counters; an independent observer decodes existing frames once and reads only subsequent frames. Pending counts are checked after every call.

| Role | Median cold status | Median operations/sec | Median trial p95 warm/incremental status |
| --- | ---: | ---: | ---: |

There was no measured status baseline; these are absolute cleanup timings. Status enumeration and payload work run outside producer/consumer locks. Counters are operational snapshots and may change concurrently.

## Continuous load and recovery

The final 150-second run processed **1,500,000 distinct events** at **9,999 producer events/sec** with 100-event enqueues and 16 workers. Handoff p95 was **1017.1 ms**, p99 **1071.1 ms**, and maximum **1145.0 ms**. The one-second rollover policy remains the principal handoff delay.

Maximum observed backlog: 11,600 events. Final drain: 133.0 ms. After drain, pending/in-flight counts were zero and 118,801,560 bytes remained for recent deduplication indexes. ## Validation and operation

Passed: **749 analytics tests**, **3 collector health/generated-wiring tests**, and processor/server/runner Kotlin compilation. Tests cover incomplete journal appends, corrupted payloads and lengths, snapshot-before-truncation crashes, journal regrowth after an observer sees the snapshot, out-of-order acknowledgment/retries, concurrent compaction/status, pending-segment open failures, retryable expired-index cleanup, deduplication and real grouped disk-to-Iceberg commits.

Production analytics coverage is **98.76% line / 89.90% branch**, below the unchanged **99% / 98%** gates. Benchmark source sets are excluded from production coverage using the same policy as the Core module; no production classes were excluded. Overall coverage, native execution, deployed broker-free topology and deployment-specific full-pipeline/load acceptance remain open.

The protected-header spool format is version 2. Earlier unreleased formats require draining with their matching binary or selecting a fresh spool directory; accepted data is not automatically converted or deleted.
