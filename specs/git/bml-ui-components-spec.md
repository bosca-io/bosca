# Git BML UI components

The Nuxt components in `web/packages/ui/src/components/` are the behavior and presentation reference for the local BML controls. Git composes those controls with domain-specific components. Later extraction into a Bosca BML UI library must retain these boundaries and capabilities.

## Component contracts

| --- | --- | --- |
| `ui-page` | `PageShell.vue` | Scrollable content allocation, full-height workspaces and narrow forms. Filled pages have a default 16px gap and an explicit compact 8px gap; spacing is owned by the component's scoped styles. |
| `ui-input` / `ui-field` | `TextInput.vue` | Native validation and form attributes, regular and compact heights, monospace values, shared label spacing, placeholder and disabled treatments. |
| `ui-search-input` | `SearchInput.vue`, Studio `git/search.vue` | Prominent query field with search icon, clear action, action slot and accessible label. Live results preserve query focus and caret; empty and disabled states remain usable. |
| `ui-segmented-control` | Studio `git/search.vue` mode toggle | Compact labelled choices with optional icons, native hidden form value, radio-group semantics and Left/Right/Home/End keyboard selection. The shared Nuxt package has no generic segmented-control export today. |
| `ui-button` | `Button.vue` | Primary treatment, icons, three sizes, disabled state and stable loading presentation; attributes and declarative BML actions pass through. Progress replaces the visible contents while retaining their layout and accessible name. Declarative actions use BML's existing busy/pending attributes. |
| `ui-spinner` / `ui-loading-state` | Studio repository and README loading states | Reusable muted progress row with accessible status text, regular/compact presentation and one spinner with reduced-motion support. The spinner is a local addition; the shared Nuxt package has no generic Spinner export today. |
| `ui-select` | `Select.vue` | Native form values with an enhanced trigger, searchable options, disabled options, async search, loading/error/empty feedback, stale-response rejection, retained selected labels, custom choices, multiple selection, removable tags, tag limits, keyboard navigation and viewport positioning. A muted 13px Lucide chevron rotates when open; the native fallback uses the same glyph and inset. |
| `ui-copy-field` / `ui-copy` | Studio repository clone field, `TextInput.vue`, `Button.vue`, `Tooltip.vue` | Selectable read-only value with an aligned inline copy icon, stable check-icon feedback, accessible status and a manual-copy fallback. Copy fields select their value on focus; clipboard failure selects it and displays recovery text. |
| `ui-popover` | `Popover.vue` | Interactive content in the browser top layer, positioned at its trigger within viewport bounds. It repositions on scrolling, resizing and content-size changes; Escape/outside dismissal, trigger focus recovery, field focus and control/content accessibility links. |
| `ui-dialog` | `Modal.vue` | Title, subtitle, icon, three widths, disabled triggers, native modal background containment, first-field or Cancel focus, keyboard focus wrapping, Escape/backdrop/Cancel dismissal, restored trigger or nominated external-control focus and recovery after server action patches. Preserved dialogs restore native modality and active-field focus after an ancestor's polling patch. Form bodies scroll while their footers remain visible. |
| `ui-tabs` | `PageHeader.vue` tab layout | Full-width divider, ordinary navigation links, a trailing slot for counts or metadata, responsive More menu, active-tab retention, outside/Escape dismissal and resize cleanup. The More chevron uses the Nuxt 12px size and open-state rotation. |
| `ui-page-heading` | `PageHeader.vue` | Breadcrumb navigation, title and subtitle, icon, badge and action slot. Descriptions can remain beside the title or explicitly appear below it. Optional title-aligned actions share the title's centerline on desktop and wrap beneath the identity on phones. |
| `ui-card` / `ui-section-heading` | `SectionCard.vue` | Shared card surface filling its parent allocation, optional padding, title/subtitle and a header action slot. Composition uses default slots, which BML supports today. Code workspaces remain separate, flat surfaces. |
| `ui-empty-state` | Studio empty panels | Centered icon, title, explanatory text and an optional action slot. |
| `ui-switch` | `Switch.vue` | Compact toggle with native checked/form semantics, switch accessibility role, keyboard operation, optional description, disabled state and a visible focus ring. Git boolean preferences and configuration use this control. |
| `ui-icon-button`, `ui-icon-link`, `ui-icon` | `Button.vue`, `Icon.vue`, `Tooltip.vue` | Square icon actions with accessible labels and hover/focus tooltips; links retain native navigation/download semantics. Canonical Lucide SVG paths, packaged ISC attribution, shared control sizing and text/icon centering. Extra-small icon buttons use a 24px square for diff-line actions. |
| `ui-tooltip` | `Tooltip.vue` | Bosca background/border/typography, 200ms delay, top/bottom/left/right placement, no arrow or animation, viewport fit, hover and keyboard-focus display, Escape dismissal, `aria-describedby` and lifecycle cleanup. |
| `ui-view-tabs` | `Tabs.vue` | Underline tabs for local views, selected/tab-panel accessibility, roving keyboard focus and Left/Right/Home/End selection. Labels center with adjacent icon actions and the active underline meets the toolbar divider. Repository navigation stays in `ui-tabs`. |
| `ui-tree`, `ui-tree-item` | Studio `ChangedFileTree.vue`, `ChangedFileTreeNode.vue` | Full-row folders, Lucide folder/open-folder/file icons, 14px nesting steps, active-file highlight, truncated labels with full-path titles, ARIA levels/selection/expansion, one tab stop, Arrow/Home/End/type-ahead navigation and focus recovery after a server patch. The shared Nuxt UI package has no exported generic Tree today; these local primitives follow Studio's domain tree. |
| `ui-disclosure-heading` | Studio `GitHubSyncHistory.vue` and repository detail disclosures | Native disclosure semantics with a styled Lucide chevron, consistent text/spacing and hover/focus treatment, replacing browser-default triangles. An optional framed heading provides the surface/divider for diff files. The shared Nuxt package has no exported generic Disclosure today. |
| `ui-confirm-dialog` | `ConfirmModal.vue` | Shared modal explanation and action footer, failed-action reopening and explicit confirmation outside table rows. |
| `ui-badge` / `git-status-badge` | Studio status presentation | Neutral, information, success, warning, error and purple treatments; readable labels and state dots. Git chooses the meaning of each state. |
| `ui-time` | Studio timestamp formatting | Native `time` semantics, absolute UTC or relative labels and the original timestamp on hover. Optional `inheritTypography` adopts the surrounding font, line height and color for labelled metadata; other uses retain the component's default typography. |
| `ui-alert` | Studio form feedback | Error and success tones, with error as the default. |
| `ui-source-view` | Studio CodeMirror views | Numbered read-only CodeMirror, wrapping and bounded command snippets as well as full-height file viewing. |

`ui-select` keeps its underlying `<select>` for form submission and validation. Its client controller does not call GraphQL. An asynchronous consumer handles the bubbling `selectsearch` event and resolves typed option records. The Git owner picker adapts `GitOwnerSearch.search` to this contract and retains the profile slug/ID in each label. It emits `ownerselected`; the repository filter submits its GET form immediately.

A dialog's `forceOpen` recovers initial/open and failed-submission state. Its `completed` signal closes a successful action once, permitting a later action to reopen the same dialog. Scripts belong at component scope outside islands. Islands own live models and declarative actions; reusable controls own browser presentation and accessibility.

## Source mapping

The BML controls remain local to Git while sharing the vocabulary and contracts of the existing Nuxt library:

- Actions map to [Button.vue](../../web/packages/ui/src/components/Button.vue), [Icon.vue](../../web/packages/ui/src/components/Icon.vue) and [Tooltip.vue](../../web/packages/ui/src/components/Tooltip.vue). `ui-icon-link` adds native anchor/download semantics to that presentation.
- Local Preview/Source selection maps to [Tabs.vue](../../web/packages/ui/src/components/Tabs.vue). Route navigation maps to [PageHeader.vue](../../web/packages/ui/src/components/PageHeader.vue).
- Folder and changed-file rows map to [ChangedFileTreeNode.vue](../../web/projects/studio/app/components/git/ChangedFileTreeNode.vue) and [ChangedFileTree.vue](../../web/projects/studio/app/components/git/ChangedFileTree.vue). These are Studio domain components today, not an existing shared Nuxt Tree export. BML's reusable tree owns presentation/keyboard behavior; Git owns pinned loading and persisted expansion.
- Expandable detail sections retain native semantics and follow the details used by [GitHubSyncHistory.vue](../../web/projects/studio/app/components/git/GitHubSyncHistory.vue). `ui-disclosure-heading` gives those sections a shared styled heading instead of a browser-default marker.
- Pull-request composition follows [Studio's pull-request detail](../../web/projects/studio/app/pages/git/pulls/[id].vue) and [pull-request list](../../web/projects/studio/app/pages/git/pulls/index.vue). `git-pull-status` shares Open/green, Merged/purple, Closed/red and Draft/neutral presentation across headers, rows, dependencies and merge plans. `git-pull-review-status` gives reviews readable outcomes and a neutral dismissed state. These Git-specific labels compose the generic badge, button, tooltip, card and dialog controls rather than becoming generic UI-library policy.

The future BML library can extract the generic `ui-*` components and their client controllers. Repository GraphQL, author metadata, routes and live models remain in Git.

Search input presentation follows [SearchInput.vue](../../web/packages/ui/src/components/SearchInput.vue); the page's mode toggle and result layout follow [Studio search](../../web/projects/studio/app/pages/git/search.vue). The BML search component owns repository/ref criteria and result navigation. The input and segmented control remain generic components.

## Search composition

The search page puts a prominent query above one aligned row of compact Content/Paths, repository and branch/ref controls. Repository choices include the name and slug, with an ID only when those labels collide. Choices cover accessible active repositories independently of the remembered repository-owner filter; an explicitly selected archived repository remains available.

Typing waits 300ms before a read-only BML action; Enter submits immediately. In-flight actions coalesce to the latest criteria. The query and caret survive result patches, obsolete results remain hidden, and successful criteria update the URL with query, repository, mode and ref. Clearing restores the initial prompt. Repository changes reset to its default branch while retaining the query. Content mode accepts branches because the content index is branch-based; switching from a tag/commit resets to the default branch. Paths mode accepts branches, tags or commit SHAs and pins result links to the resolved commit.

Results use whole-row native links with visible keyboard focus. Content rows show path, line and safely escaped snippets with literal, case-insensitive query highlighting. A Markdown line result opens its numbered Source view. Paths rows show file/folder/link icons, names, full paths, sizes and symbolic-link/submodule labels. Empty repositories, unsupported content refs, no matches, API failures and transport failures have distinct visible states. Transport errors permit retry while retaining the query. Generic controls contain no repository queries; server actions use the existing GraphQL backend abstraction.

## Control dimensions

Regular inputs, selects and buttons use a 32px border-box height. Compact controls use 30px; extra-small buttons use 24px. Inputs, select triggers, buttons, button links and popover triggers use a normal line height independent of the document's prose typography. Inputs and select triggers share 10px horizontal padding and 13px regular / 12.5px compact text. Button/select leading icons use 14px; extra-small button icons use 12px. Select chevrons use Nuxt's muted `--fg-4` color and 13px size, with an 11px right inset including the border. Enhanced menus rotate their chevron 180 degrees when open and highlight the trigger border. The native fallback suppresses the browser arrow and shows the same centered Lucide glyph. Text and icons center together within the control; repository menu actions retain a shared left inset and typography. These dimensions follow the Nuxt input and select source and align adjacent actions with their controls.

Geist and Geist Mono are packaged with the Git UI, using the existing Bosca font assets and their license. The global font stylesheet defines their weights and Unicode subsets; Git server serves the versioned WOFF2 resources from the same origin. This makes the declared design fonts available without a third-party font request. Font files and their stylesheet are included in native resource metadata.

Fields use 18px label lines and a 6px label/control gap. Owner captions use the same metrics. Stacked forms use 14px gaps, and their actions fit their labels instead of stretching across the grid. Forms reset browser margins, including the branch/Clone header row. Authentication retains its own 38px inputs and theme treatment. The prominent search field uses 40px, with 30px filters and a 30px segmented control beneath it. Segmented text/icons use the same normal line-height and centering contract as buttons.

Dropdown searches use a 30px toolbar with a bottom divider and no nested outlined input. Single-line choices use the Nuxt option padding and typography; the popup still follows its trigger width and fits above or below the available viewport space.

Route/state tab dividers span the content width on repository lists, pull-request lists and repository panels. Trailing metadata occupies the shared tab row's slot, while overflow measurement uses the space remaining for links. Repository and pull-request lists use the same 12px header-to-tabs gap even when a panel wraps the tabs. Pull-request numbers use Studio's compact badge and a 6px title gap. Local Preview/Source controls remain compact inside their full-width file toolbar.

Shared section stacks and their cards fill the available width, including Compare, Statuses and repository panels. Forms may retain readable control widths and grid columns retain their assigned allocation. Section stacks have no independent page-width cap.

Markdown follows Studio's README content padding: 24px/28px/32px on desktop and 18px/16px/24px on narrow screens. Its article fills the file surface and stays left aligned. Markdown view labels share that left inset; the toolbar uses a 46px row with its file actions centered alongside the tabs. The active underline meets the toolbar's divider.

Search, deferred files, asynchronous choices and pending action buttons share the 14px spinner. Extra-small buttons use 12px. All spinners use the same 0.8s timing and stop under reduced motion. Pending button contents become transparent while retaining their space and accessible name. The file fallback shows progress during loading, an alert and compact Retry action only after failure, and replaces both when files load. Closing an asynchronous select clears its busy state, and stale responses remain rejected.

## Git composition

The clone action opens a compact read-only URL field with its copy icon in the same 30px row. The URL selects on focus. Success uses a temporary check icon without changing field width; clipboard failure selects the value and shows manual-copy guidance. The popover follows its trigger in the top layer, stays within the viewport and closes on Escape or outside interaction. This composition follows Studio's repository clone field and the shared Nuxt input/button/popover presentation.

The sidebar binds `model.expand` only when rendering a directory row. File rows remain native anchors with no inherited folder action; pointer clicks and Enter follow their repository/ref/path URLs. This boundary preserves browser navigation semantics while folder loading stays deferred and commit-pinned.

`git-repository-heading` composes the shared page heading with branch, PR-creation and clone controls. The description and repository stats share a compact desktop metadata row, with stats right-aligned beneath the controls. Phones stack those fields. Repository pages select compact page spacing explicitly; header-to-tab spacing is 12px. Count labels use singular forms for one commit, branch, tag or contributor. The repository-specific model and controls remain outside the generic heading.

Repository creation/import use dialogs with readable enum labels and fixed action footers. Creation initializes a README by default, and name input suggests a slug while retaining explicit slug edits. Extra initialization templates are expandable. Pull-request creation, review submission, assignment and dependency selection use the same dialog shell. PR creation groups target repository/branch beside source repository/branch in a wide desktop dialog, stacking them on narrow screens. Repository changes retain the title, description and draft state while replacing unavailable branches. The global dialog works without a preselected repository. Initial dialog focus uses the first visible field or Cancel, and select enhancement transfers native-field focus to the replacement control.

Pull-request detail exposes Overview, Files Changed and Reviews as separate links. Its header groups title, number and lifecycle badge above readable author, branch context and timestamps. Overview places description, merge readiness/status checks, recent reviews and changed-file summary in the main column. Assignees and dependencies share one compact sidebar card. Metadata actions use labelled icon controls; important lifecycle actions keep explicit text. Review outcomes read Approved, Changes requested, Commented or Dismissed. Checks use separate context, description and outcome columns with a summary badge and safe external links. Mergeability describes branch compatibility; the API still enforces required checks and reviews. Optional failed checks alone do not disable merge.

Detail headers share one desktop metadata row: author and branch context on the left, timestamps aligned to the right beneath the primary action. Timestamp labels and values share a 12px font, 18px line height and text baseline through `ui-time`'s inherited typography. Narrow screens wrap the metadata with a 6px row gap. Long titles and branch names wrap within the available header width. The full-width tab divider and its shared spacing remain the navigation boundary.

Files Changed uses a compact count/action toolbar followed by `git-pull-files`, a 220px changed-file sidebar beside the diff column. This follows Studio's two-column review layout; at 800px and below the sidebar stacks above the diff. The component owns layout and projects the existing review model's diff content through its slot. Tree links retain native file-fragment navigation and keyboard folder expansion. The repeated Files changed section heading is omitted because the active tab names the view.

Diffs use framed disclosure headings, aligned line numbers, standard spaced hunk captions and addition/deletion markers. A zero-line text hunk produces an explicit empty-file notice; a file with no available hunks retains its unavailable-text-diff message. A compact line-comment icon appears on pointer hover or keyboard focus and remains visible on touch devices. Its editor opens beside the selected diff line and retains failed drafts. Missing line-number sides travel as zero in primitive BML action arguments and normalize to nullable values inside the Git model. The displayed diff remains the validation source. Reviews retain history and thread resolution. Drafts must be marked ready before review submission, matching the Git service contract.

Pull-request lifecycle changes use confirmation dialogs. Merge pull request opens a Merge method form, then presents the reviewed dependency plan and its statuses. Changing method keeps the dialog open and retains the previous choice; submitting rechecks the source commit and plan. Known merge conflicts disable the trigger, and blocked dependency plans disable final confirmation. Closed pull requests offer reopening; merged requests show their outcome without close/review controls. Reviews group author, review state and time in a card header, with comment threads beneath them.

Repository Pull requests, Pipelines, Statuses, Secrets and Settings stay on the repository route, with the active tab and contextual filter/panel/paging links. Explicit repository selection is independent of a remembered owner filter; archived repositories remain scoped and disable PR creation. App settings are a collapsed sidebar group during code browsing and expand on settings routes. Repository synchronization is a secondary action in Metadata. Settings use section headers with creation actions, dialog forms and centered empty states. Metadata presents current details and opens editing in a dialog; rename has its own action card. Webhook rows show endpoint, active state, event labels and creation time. Protection rules show all policy badges and open the same form for creation/editing. Permissions use group names and readable action badges; secrets never expose stored values. Maintenance has separate Storage, GC and Repair cards with explicit confirmation dialogs.

Repository lifecycle actions are named menu items followed by a confirmation dialog. File/folder actions use the same dialog primitives. Edit/rename, delete, new file/folder, download, raw view and clone-copy actions use labelled icons with the shared Tooltip presentation. Markdown Preview/Source use the Nuxt Tabs treatment beside those actions in one toolbar. The ref picker applies selection directly without a redundant arrow submit control. An unborn repository has one setup view and a copyable clone command. The file sidebar and changed-file tree compose the same reusable tree controls. The Files heading is static; folders expand through the full row instead of separate boxed arrows. Navigation opens the selected file’s ancestors, retains per-commit folder expansion and highlights its active row. The file sidebar uses a deferred island with scalar navigation inputs; its live model and pinned tree query execute after the page shell. Folder expansion remains on demand and restored per repository/commit. The fallback distinguishes loading from failure and offers retry. Scripts remain at component scope.

Agents have a section filter and registration/deregistration dialogs, including one-time token handling. Agent details group status, current commands, recent jobs and editable settings into cards. Orchestrator settings keep both JSON editors and every provider/default/limit field; status polling is separate from their drafts.

Pipelines use compact rows grouped by repository and owner, with latest-run status, ref, commit, duration and time. The repository Pipelines tab retains the repository header and navigation, shows recent runs and their jobs, and puts complete run history behind a disclosure. Manual runs use a dialog; selecting a ref reloads the definitions through a declarative server action and retains compatible input values. Pipeline titles open the latest run. Run dialogs retain the selected owner filter. Run details use a metadata summary, expandable job cards, colored status badges, readable timestamps and artifact rows. Run/job actions have explicit dialogs. The build-anyway reason and active dialog survive polling, and rejected submissions retain their reviewed reason. Log subscriptions, paging, pause/resume and follow-output controls remain independent.

GitHub mappings separate the mapping form and record table, hide unnecessary pagination counts, retain identity identifiers, and confirm removal in a dialog. Synchronization history uses a card with tabs, observed ref states and meaningful empty views. Synchronization and shared credentials have focused dialogs; pairing keeps its editable branch filters and enablement control. Search, comparison and commit statuses use the same card and record presentation.

## Verification and extraction

The isolated browser suite exercises owner disambiguation, stable trigger width, automatic filtering, async loading/empty/error recovery, rejected creation/review drafts, modal fit/focus/Escape/backdrop behavior, merge-plan preparation and strategy changes, select keyboard choices, webhook multi-selection and tag removal, responsive tab overflow, code editing, Markdown images and the screen matrix. The matrix additionally measures control heights, text-range and icon centers, combined horizontal content centering, and top/bottom alignment for controls sharing a row, plus modal widths and compact dropdown search/option dimensions. PR checks compare timestamp label/value fonts and actual text bounds for both older dates and fresh “just now” labels, measure the sidebar/diff layout, and exercise empty-file tree navigation and inline comments. It verifies that both packaged design fonts load and that repository menu actions align. JVM tests exercise compiled pages and action contracts for all three pull-request views and serve every font over real HTTP with its binary MIME type.

This is a reference for the controls implemented in Git, not a claim that the entire Nuxt UI package has been ported. Nuxt's per-option icon rendering and arbitrary accent/width customization have not been copied. Before extraction, compare each exported component against its Nuxt source and test its supported configurations; avoid exporting unverified promises or Git-specific profile/search behavior.
